# CAT-OS:适用于 Claude Code 和 Codex 的 AI 操作系统入门套件

> 🌐 English version: [README.md](README.md)

一套免费、MIT 许可的入门套件,可以把 Claude Code 或 Codex 变成你的个人 **AI 操作系统(AI OS)**。适用人群:所有在做自动化的人——独立创业者、小企业经营者、管理者、创作者、AI 顾问。可搭配配套大师课视频一起使用。

套件通过 `/onboard` 访谈实现个性化定制。想让它更懂你的业务、偏好或计划时,随时用 `/grill-me`。用 `/link` 让新信息可被检索,用 `/audit` 验证系统,用 `/level-up` 每次弥合一个有用的差距,用 `/3d-brain` 以交互式星球的形式探索你保存的知识。

> **CAT-OS** 代表 **AI Automation Society OS**——这是 Nate 为他的社区成员 [AI Automation Society](https://www.skool.com/ai-automation-society) 设计的 AI OS 搭建方式。套件本身是通用的(对任何人都适用),但其结构反映了 AIS 成员在这个基础之上运营自己业务的方式。

## 如何判断它在发挥作用

三个可感知的**成功指标**告诉你 AI OS 确实在改变你的工作方式。不是 KPI——没有客观的度量标准。它们是会出现在你一周里的真实体验。

**1. 团队主动来问:**

> *"队友发消息问你一个问题。你意识到你的 AI OS 能回答得更好、更快,还带精确出处——即使你醒着有空也是如此。于是你也去问你的 AI OS。这一刻,你不再是自己知识的瓶颈。"*

**2. 减少上下文切换:**

> *"你不再打开新标签页。你不再启动桌面应用。当有新事情出现,你的第一反应是问 AI OS,而不是连开六个窗口。思考性工作的默认界面发生了转移。悄无声息。持续复利。"*

**3. 知识离开你的大脑:**

> *"你不再费力去记业务事实。你不用回想上季度做了什么决定,或客户在那次会议上说了什么。你信任检索。AI OS 掌握真相,你掌握问题。"*

**个人基础 → 企业 AI 就绪度。** 一旦这些指标在一个人身上显现,同样的数据架构就能支撑其他一切。在你已经收集的数据上搭定制仪表盘。在你已经接好的连接上叠加自动化。团队推广时,每个人都有自己的 AI OS。*一家每个运营者都运行着个人 AI OS 的公司,才是真正 AI 就绪的公司。*

套件先教你搭好个人 AI OS。一切从这里向外扩展。

## 两大框架

套件教授两个互补的框架。**先学三 M,再学四 C。** 没有先重塑大脑,架构就只是一个文件夹结构。

### 三 M——操作者大脑(你如何思考)

| M | 一句话概括 |
|---|---|
| **心态(Mindset)** | 默认转换、功能拆解、好奇规则。*"这里能在多大程度上利用 AI?"* |
| **方法(Method)** | 找到约束 → EAD(消除、自动化、委托)→ 映射流程 → 选择自主级别 → 关联 KPI。 |
| **机器(Machine)** | 乐高原则、验证链、自行车方法、实习生规则、终止开关。*无聊即美。工作流胜过智能体。* |

完整拆解见 `references/3ms-framework.md`。`/level-up` 技能每周带你过一遍这三者。

> *The Three Ms of AI™ 是 Nate Herk 的商标。© 2026 Nate Herk。*

### 四 C——架构(你构建什么)

| # | 层 | 一句话概括 | "这一层已就位"的检验 |
|---|---|---|---|
| 1 | **语境(Context)** | 了解你的业务 | 一个全新的助手会话,无需翻阅资料就能回答"这家公司是做什么的、这里有谁在工作?" |
| 2 | **连接(Connections)** | 够得着你的东西 | "我明天日历上有什么、哪些任务快到期?"→ 实时数据,无需粘贴 |
| 3 | **能力(Capabilities)** | 知道怎么干活 | 一句短语触发一个多步骤工作流,产出一件成品 |
| 4 | **节奏(Cadence)** | 不用人催也能跑 | 合上笔记本。一份简报落进收件箱。队友给它发消息,得到一个真实的回答 |

**品牌口号:** Context. Connections. Capabilities. Cadence.(语境。连接。能力。节奏。)

> *The Four Cs of an AI OS™ 是 Nate Herk 的商标。© 2026 Nate Herk。*

依赖关系:语境不可跳过。连接和能力可以并行建设。节奏放在最后——不要去自动化那些手动都跑不通的工作流。

## 随套件附带的 6 项技能

套件包含初始设置、持续性上下文访谈、路由、验证、每周改进工作流,以及一个可用的 3D 知识浏览器。随着你的 AI OS 成长,你可以扩展这套结构。

| 技能 | 类型 | 何时运行 |
|---|---|---|
| `/onboard` | 设置向导(一次性) | 第 1 天,克隆后立即进行。7 个问题的访谈。生成第 1 天文件集,并填充共享的 `CLAUDE.md` 和 `AGENTS.md` 操作手册。 |
| `/grill-me` | 上下文访谈存档 | 任何时候你想展开一个计划或补充更多上下文。一次只问一个问题,并把每个回答保存到 `brainstorms/`。 |
| `/audit` | 基于证据的检查 | 设置完成后、重要修复之后,以及建设期间每周运行。检查路由、新鲜度和 Claude/Codex 兼容性,为已验证的可靠性打分,并自动保存带日期的报告。 |
| `/link` | 路由助手 | 添加项目、文件、文件夹或重要资料来源时。添加最小但有用的手册/索引路由,并检查它能解析生效。 |
| `/level-up` | 周期性思考技能 | 第 14 天,之后每周。三 M 访谈(心态 → 方法 → 机器)。一次运行 = 交付一个成果。 |
| `/3d-brain` | 交互式知识浏览器 | 为你的大脑选择名字和分类。基于你选定的文件构建本地 3D 星球,支持搜索、阅读笔记、Cinema 影院模式,以及分支式成长回放。 |

`/audit` 检查 AI OS 能否可靠地找到自己的信息并完成有用的工作。Rubric v2 评分依据是证据,而不是文件夹数量、API 密钥,或名字叫 "daily" 的技能。缺失或未经验证的层会封顶总分;已安装的技能无法弥补缺失的连接或执行历史。报告包含五项检索探针、过期缓存与来源权威性检查、操作手册差异、技能包兼容性,以及最多三项按优先级排序的改进建议。它会区分已确认的缺陷、待验证的缺口、有意为之的运行时差异,以及可选的改进。分数衡量的是已验证的运行可靠性,而不是整体有用性。旧评分标准下的分数需要建立新基线。

**自动审计历史:** 每次 `/audit` 都会在 `audits/` 中保存一份唯一的、带日期的 Markdown 报告,并与相关的既往报告进行比较。发现项保留其 ID,并被跟踪为:新增、仍然开放、已解决、重新打开、未复检,或不再适用。判定"已解决"需要新的证据。分数比较会区分真实的修复、证据变好和覆盖范围变化。早期报告会被保留;除新生成的本地报告外,被检查的系统保持不变。审计报告默认被 gitignore,因为它们可能包含私密的项目上下文。明确要求不保存时,可以覆盖这一默认行为。

`/link path/to/project "用途说明"` 让新资料可被找到,而无需把其内容复制进操作手册。它会遵循项目已有的 `AGENTS.md`/`CLAUDE.md` 约定,只在目标或用途不明确时才提问。热缓存是可选项,这些技能绝不会主动创建它。

`/grill-me "帮我说清楚我的业务是怎么运作的"` 会把你脑子里的东西变成已保存的上下文。每个回答都会立即检查点式地写入 `brainstorms/` 下带日期的 Markdown 文件,因此你可以随时暂停和继续。当你要求构建或更新 AI OS 上下文时,已确认的事实会加入相应的上下文页面,并附指回访谈的链接。未定型的想法保持原样标注。访谈记录默认被 gitignore。初始设置用 `/onboard`,之后随着业务和思考的演进使用 `/grill-me`。

`/level-up` 把审计证据转化为一个改进。对现有工作流的一次经过验证的修复也算数;不一定非要再写一个新技能。修复完成后重新运行 `/audit`。重复使用和定时运行的积分来自长期的真实执行。

## 快速开始

### 在 3D 中看见你的 AI OS

把你不断增长的笔记、项目和助手记忆变成一个可以探索的地方。看到哪些想法相互连接,搜索你记得的某样东西,打开原始笔记,发现需要关注的知识。成长回放也给你一种可视化的方式,向别人展示你的 AI OS 里都有什么。

[![观看 3D 大脑从一个想法成长为相互连接的知识星球](docs/media/3d-brain-preview.gif)](https://github.com/nateherkai/AIS-OS/raw/refs/heads/main/docs/media/3d-brain-demo.mp4)

上面的预览播放完整的成长序列。**[下载原始的 36 秒视频](https://github.com/nateherkai/AIS-OS/raw/refs/heads/main/docs/media/3d-brain-demo.mp4)** 可以全分辨率播放。这段录屏展示的是 Nate 的 HerkBrain。该技能会用你选择的名字、分类和已保存的知识来构建属于你的那一个。

在 Claude Code 中运行 `/3d-brain`,或在 Codex 中运行 `$3d-brain`。它会询问你的大脑叫什么名字、展示哪些分类,并给出建议的来源文件夹。然后使用附赠的应用模板创建 `apps/3d-brain/`。你的名字、分类、颜色和路径都保存在本地配置中。

使用 **Play demo** 观看大脑从一个单一想法成长为相互连接的分支。整个播放过程中,你都可以拖拽旋转视角、滚动缩放。**Cinema** 提供一个干净的演示视图。回放遵循的是真实的笔记连接;它不是历史时间线。

需要 Node.js 22 或更新版本。渲染器已预构建,因此应用无需安装依赖,直接用 `node serve.mjs` 即可运行。它读取本地 Markdown/文本,以及可选的精选 Codex 记忆。Claude 记忆、会议纪要和视频知识可以使用选定的 Markdown 文件夹。其他格式或在线服务需要导出,或一个经过测试的适配器。应用只停留在 localhost;个人配置和生成的数据都被 gitignore。

完整的[技能包](.claude/skills/3d-brain/README.md)包含源代码、浏览器 bundle、配置文档、许可声明,以及一个使用虚构数据的验证脚本。

### 在 Codex 中使用这套套件

六项技能同样安装在 `.agents/skills/` 下。使用技能选择器(Codex CLI 或 IDE 扩展中的 `/skills`),或输入 `$` 并选择 `audit`、`link`、`onboard`、`level-up`、`grill-me` 或 `3d-brain`。Codex 通常会自动检测技能更新;如果列表没有刷新,重启它即可。

`.claude/skills/` 仍然是编写源头。编辑某个技能之后,运行 `bash scripts/sync-codex-skills.sh <skill-name>` 重新生成它的 Codex 副本、配套文件和菜单元数据。onboard 的录入模板和 level-up 的框架随各自技能一起分发;现有项目保留自己的规范上下文路由。

### 首次设置

1. **克隆仓库**到你机器上的一个工作文件夹。
2. **在 Claude Code 或 Codex 中打开它。** 在 Claude Code 中运行 `/onboard`,或在 Codex 中选择 `$onboard`。诚实地回答 7 个问题。语音样本必须粘贴,而不是描述。大约需要 15 分钟。结束时生成第 1 天文件集。
3. **使用一周。** 带来真实的问题。做出真实的决定。让助手把有意义的决定记录到 `decisions/log.md`。
4. **第 7 天:** 运行 `/audit`。阅读四 C 差距报告。选一个差距来弥合。
5. **第 14 天:** 运行 `/level-up`。三 M 访谈会浮现出一个值得构建的自动化。把它构建出来。
6. **随着成长:** 用 `/grill-me` 捕获新上下文,用 `/link` 接入新来源,用 `/level-up` 做一个改进,再重新运行 `/audit` 验证它。

## 仓库结构

```
CAT-OS/
├── README.md
├── CLAUDE.md                        ← Claude Code 的共享操作手册
├── AGENTS.md                        ← Codex 的对应操作手册
├── EXPANSIONS.md                    ← 随着你成长要添加的东西
├── LICENSE
├── .gitignore
├── aios-intake.md                   ← /onboard 的事实来源。随时编辑 + 重新运行。
├── connections.md                   ← 你的 AI OS 可触达的每个系统的登记表
├── context/                         ← 关于你和你的业务(由 /onboard 填充)
├── references/
│   └── 3ms-framework.md             ← 操作者大脑
├── decisions/
│   └── log.md                       ← 只追加的记录:决定了什么、为什么
├── archives/                        ← 旧东西。不要删除。移到这里。
├── brainstorms/                     ← 由 /grill-me 创建;已保存的访谈(gitignored)
├── audits/                          ← 首次审计时创建;带日期的私密报告(gitignored)
├── scripts/sync-codex-skills.sh      ← 重新生成 Codex 技能副本
├── .agents/skills/                  ← 全部六项技能的 Codex 副本及配套文件
└── .claude/
    └── skills/
        ├── onboard/SKILL.md
        ├── audit/SKILL.md
        ├── level-up/SKILL.md
        ├── grill-me/SKILL.md
        ├── 3d-brain/                ← 技能、可移植应用模板、文档和验证脚本
        └── link/SKILL.md
```

随着你成长要添加什么(`projects/`、`templates/`、`scripts/`、`.claude/agents/`、子 OS 文件夹等),参见 `EXPANSIONS.md`。
